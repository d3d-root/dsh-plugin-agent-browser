## [2.0.0] — 2026-11-07

Мажорная версия не из-за ломки API: все 35 инструментов и настройки остались
прежними, ничего переучивать не нужно. 2.0 — потому что в 1.x три инструмента
отвечали неправду, и это выяснилось только на живом браузере, а не тестами.
Теперь ответы проверяются сквозным тестом, а не обещанием.

### Исправлено

- **`browser_wait` всегда отвечал «не появилось».** Хост читал `result.found`, а
  клиент кладёт результат в `{ value: { found } }`: условие никогда не
  выполнялось, и инструмент врал даже когда текст был на экране. Теперь ждёт и
  честно сообщает, сколько ждал.
- **`browser_find_in_page` всегда отвечал «не найдено».** В Electron 44
  `webview.findInPage()` не присылает `found-in-page`
  ([electron#54199](https://github.com/electron/electron/issues/54199)), поэтому
  вызов висел до таймаута и возвращал ноль совпадений. Плагин ждёт событие
  400 мс, затем считает совпадения сам по `innerText` и подсвечивает первое
  через `window.find`. Число совпадений верное; подсветка — только первого.
- **`browser_extract` падал на пустом селекторе поля.** `fields: { title: "" }`
  — естественный способ сказать «текст самой карточки» — приводил к
  `querySelector('')` и исключению на всю страницу. Теперь пустая строка
  означает текст узла, а битый селектор портит только своё поле.
- **`browser_screenshot` с относительным путём писал не туда.** `shot.png`
  оказывался в каталоге профиля DSH (`~/.dsh/profiles/desktop/`), потому что
  путь считался от `process.cwd()` процесса, а не от рабочего каталога чата.
- **`browser_screenshot` висел 30 секунд на фоновой вкладке.** Chromium не
  отрисовывает скрытый `<webview>`, и `capturePage()` не отвечает вовсе. Теперь
  съёмка ограничена таймером, а инструмент отвечает прямо: вызовите
  `browser_reveal`.
- **`browser_click_index` отказывал «элемент вне экрана».** Список из
  `browser_find_all` хранил только координаты, а клик искал элемент в точке —
  и не находил, если элемент ниже сгиба. Теперь список держит ссылки на сами
  элементы, а перед кликом элемент прокручивается в вид. Заодно исчезла
  отдельная ошибка, когда страница успевала перерисоваться между поиском и
  кликом.
- **`browser_download` отдавал сырое «Failed to fetch».** Сетевую ошибку и CORS
  теперь ловит код в странице и объясняет причину по-человечески.
- **`browser_click_at` кликал не в ту точку.** Событие уходило в центр
  найденного элемента: для большой обёртки это могло быть за пределами экрана,
  и страница получала неверные `clientX/clientY`. Теперь координаты берутся
  ровно те, что просил агент.

### Добавлено

- **Сквозные тесты инструментов** (`test/tools.test.mjs`): настоящий мост,
  настоящий транспорт и поддельная панель, которая отвечает тем же конвертом,
  что и клиент. Именно этот слой ловит расхождение формы ответа — то, из-за
  чего и появились три бага выше.
- `browser_tabs` показывает id вкладки: параметр `tabId` был во всех
  инструментах, но узнать сами id было негде.
- Тест на английские описания инструментов: кириллица в `description` теперь
  падает в CI.
- `npm run test:bridge`, `test:plugin`, `test:tools` — прогон по частям.

### Изменено

- Тесты регистрации переписаны: файл был сохранён в битой кодировке
  (двойное перекодирование UTF-8 → CP1251), читать его было невозможно.
- README, ROADMAP и `docs/` больше не пишут «22 инструмента»: их 35.
- README: честный раздел «Ограничения» про поиск по странице, фоновые
  скриншоты и сохранение входа.
- Тестов стало 47 вместо 33: 27 мост + 7 регистрация + 13 инструменты.

## [1.0.3] — 2026-11-07

### Изменено

- **Основной способ установки — npm.** Пакет опубликован в реестре
  (`npm i dsh-plugin-agent-browser` или `dsh plugin add`), поэтому установка
  стала короче, а в списке плагинов DSH появилась кнопка обновления.
  Установка из GitHub осталась как альтернатива.
- README перестроен: npm первым, GitHub вторым, ручной способ третьим.

### Добавлено

- Первый выпуск через GitHub Actions по Trusted Publishing (OIDC) — проверка
  всей цепочки: тег → тесты → публикация без токенов.

## [1.0.2] — 2026-11-07

### Добавлено

- **Публикация в npm и авто-выпуск без токенов.** `.github/workflows/publish.yml`
  публикует пакет по тегу `v*` через Trusted Publishing (OIDC): GitHub выдаёт
  короткоживущий токен на один запуск, npm проверяет его по доверенному
  издателю. Долгоживущих секретов в репозитории нет. Перед публикацией workflow
  сверяет тег с версией в `package.json` и прогоняет тесты, а публикует с
  `--provenance` — пользователь видит, из какого коммита собран пакет.
  Установка из реестра включает кнопку обновления в DSH.
- `prepublishOnly` прогоняет тесты перед публикацией.
- `browser_status` показывает версию плагина — первый вопрос при разборе
  проблем, особенно у установок из Git, где кнопки обновления в интерфейсе нет.
- Версия плагина пишется в журнал при старте.
- `docs/install.md`: разделы «Обновление» и «Как перейти с GitHub на npm».
- `docs/publishing.md`: разовая настройка npm и выпуск по тегу.
- `CHANGELOG.md`.

### Исправлено

- Подсказки больше не обещают, что `Ctrl+R` решит проблему рассинхрона половин:
  Electron может отдать ту же закэшированную сборку. Везде, включая баннер,
  главный совет — перезапустить приложение целиком.

## [1.0.1] — 2026-11-07

### Добавлено

- **Сторож в `index.html`.** Через 7 секунд после загрузки окна проверяет,
  загрузилась ли клиентская половина. Если нет — показывает баннер с кнопкой
  «Перезагрузить» и советом перезапустить приложение. Работает даже когда кода
  плагина в странице ещё нет.
- **Эндпоинт `/bootstrap`.** Клиент забирает токен моста сам, если не нашёл его
  во вставке `index.html`. Это снимает целый класс поломок: раньше клиент
  молча получал 403 и выглядел как «плагин не загрузился».
- Тесты на `/bootstrap`: защита от DNS-rebinding по `Host` и от межсайтового
  запроса по `Sec-Fetch-Site`.

### Исправлено

- **Регистрации обёрнуты в `ctx.effect`.** Без этого горячая перезагрузка
  плагина падала на конфликте идентификаторов, и вкладка исчезала до перезапуска
  окна.
- **Редирект больше не считается ошибкой.** `loadURL` отвергает промис с
  `ERR_ABORTED (-3)` при редиректе, хотя навигация удалась. Теперь судьбу
  перехода решают события `webview`, а отмена игнорируется.
- Вставка в `index.html` регистрируется синхронно и повторяется до 20 раз,
  независимо от готовности транспорта.

## [1.0.0] — 2026-11-07

Первый публичный выпуск.

### Возможности

- Настоящий Chromium в правой панели DSH через `<webview>`: нативная прокрутка,
  ввод, клики. Не headless и не трансляция картинки.
- **Один чат — один браузер.** Профили изолированы: разные cookie, разные
  логины, независимые сессии.
- **Несколько агентов одновременно.** Инструмент адресуется сессии своего
  агента, поэтому агенты не перехватывают команды друг друга.
- 22 инструмента: навигация, чтение, HTML, `eval`, клики (включая настоящие
  события мыши), ввод, клавиши, прокрутка, скриншоты, перетаскивание, смена UA.
- Решение капч: настоящие события мыши Chromium и «человеческая» траектория
  перетаскивания для слайдер-пазлов.
- Установка одним кликом из списка плагинов: оформлен как бандл
  (`dsh.bundle.patch`).

### Безопасность

- Транспорт только на loopback; токен обязателен и передаётся в заголовке.
- `Access-Control-Allow-Origin: null` вместо `*`.
- Ограничение тела запроса 8 МБ.
- Скриншоты пишутся только в свой каталог и рабочий каталог чата.
- Экранирование `</script>` во вставке в `index.html`.
