# Задачи разработки

Файл нужен, чтобы работа не терялась при обрыве контекста: новый агент читает
его и продолжает, не перечитывая историю чата.

## Как тестировать

Репозиторий подключён к профилю junction-ом:

```
%USERPROFILE%\.dsh\profiles\desktop\node_modules\dsh-plugin-agent-browser
  → C:\Users\magnes1um\Desktop\настройщик дсх\dsh-plugin-agent-browser
```

Правки в `lib/*` видны **после перезапуска приложения**. Горячей перезагрузки
нет: серверная половина живёт в процессе и на изменение файлов не реагирует
(проверено: правка `index.js` не даёт нового `apply()` в журнале).

Проверка: `browser_status` → строка «Версия плагина». Если на диске новее,
`browser_status` сам об этом предупредит.

Тесты: `npm test` — 94 штуки, все зелёные.

## Сделано в 2.1.3

Проверка тремя субагентами одновременно (Википедия, Hacker News, python.org)
вскрыла настоящие дефекты. Все закрыты.

### Скачки экрана между чатами

- [x] Вкладка открывается через `openTabIn(sessionId, kind)` — в store уже
      показанной сессии, без переключения экрана. Переключение осталось только
      для чата, который ни разу не открывали.
- [x] `browser_open` и `browser_reveal` шлют `focus: false`.
- [x] Если store есть, но вкладка не появилась — не переключаемся, а ждём
      (переключение здесь и было причиной скачков).
- [x] Переключения выстроены в очередь; чат пользователя берётся на момент
      задачи, а не запоминается навсегда.
- [x] Регрессионные тесты: ни один инструмент не просит `focus: true`.

### Одна вкладка на чат

- [x] `multiple: false` — адрес постоянный, DSH схлопывает повторы.
      При `multiple: true` повторный `browser_open` создавал вторую вкладку, и
      агент командовал не той, что видит пользователь (отсюда «найдено 0» на
      Hacker News и пустой `<body>` после `browser_back`).
- [x] `pruneDuplicates` убирает сирот, оставшихся от прошлых версий.

### Изоляция команд по сессиям

- [x] Команда без определённой сессии больше не уходит в чужой браузер —
      явный отказ `no-session` (раньше выбиралась первая попавшаяся панель).
- [x] Команда не уходит мёртвому клиенту (`CLIENT_LIVE_MS`): раньше висела до
      общего таймаута, и это выглядело как «страница DSH не ответила» на
      десять минут.
- [x] `panel/poll` и `client/poll` отвечают `unknown-panel` / `unknown-client`,
      и половины регистрируются заново сами.

### Прочее

- [x] `browser_back`/`forward`/`reload` ждут загрузку вместо 120 мс.
- [x] `browser_navigate` ждёт `document.readyState`.
- [x] Скриншот в фоновой вкладке: показывает вкладку на время снимка и
      возвращает пользователя.
- [x] `browser_status` предупреждает, если на диске версия новее загруженной.

## Что нельзя сделать в плагине

Проверено по коду DSH, не наши ограничения:

- **Перезапуск приложения.** `app.relaunch()` — только main-процесс, в preload
  его нет; пункт меню «Restart App and Host» есть только в dev-сборке. Поэтому
  плагин может лишь сказать, что нужен перезапуск, но не выполнить его.
- **Постоянный профиль Chromium.** `browser.acquire()` выдаёт
  `dsh-sidebar-browser-<uuid>` без префикса `persist:`.
- **Скачивания.** `will-download → preventDefault()`. Обходим через `fetch`.
- **Прокси и блокировка рекламы.** `setProxy` и `webRequest` — только main.
