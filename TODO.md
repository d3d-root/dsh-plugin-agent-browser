# Задачи разработки

Файл нужен, чтобы работа не терялась при обрыве контекста: новый агент читает
его и продолжает, не перечитывая историю чата.

## Как тестировать

Плагин установлен в профиль **копией**, а не ссылкой на эту папку:

```
%USERPROFILE%\.dsh\profiles\desktop\plugins\agent-browser   ← сами файлы
%USERPROFILE%\.dsh\profiles\desktop\node_modules\dsh-plugin-agent-browser
    → junction на plugins\agent-browser
```

Так сделано намеренно: раньше `node_modules` был junction-ом на папку проекта
на рабочем столе, и DSH не мог запуститься, если та папка переименована или
недоступна. Плагин не должен быть причиной неработающего приложения.

Чтобы обновить установленную версию, скопируйте файлы в
`plugins\agent-browser` (или переустановите плагин штатно через
`plugin_manager`). Правки в `lib/*` видны **после перезапуска приложения**.

Горячей перезагрузки нет: серверная половина живёт в процессе и на изменение
файлов не реагирует (проверено: правка `index.js` не даёт нового `apply()` в
журнале).

Проверка: `browser_status` → «Версия плагина». Если на диске новее, он сам
предупредит и скажет, как перезапустить.

Тесты: `npm test` — 122 штуки, включая проверку кодировки и упаковки.

## Если DSH не открывается

Симптом: вместо окна — экран ошибки, в журнале
`%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-*.log` строка
`desktop welcome: Web authentication failed`.

Это **не** плагин. Причина: каждый запуск DSH добавляет служебную cookie для
`127.0.0.1`, старые не удаляются; примерно после 70 штук авторизация при старте
перестаёт проходить. Переустановка той же версии не помогает.

Лечение:

```powershell
.\scripts\fix-dsh-start.ps1 -Check   # посмотреть, что найдено
.\scripts\fix-dsh-start.ps1          # починить (DSH должен быть закрыт)
.\scripts\fix-dsh-start.ps1 -Restore # откатить
```

Скрипт делает резервную копию базы с SHA-256, удаляет только cookies
`127.0.0.1` и `localhost`, проверяет `quick_check` и отказывается работать при
запущенном DSH. Cookies сайтов, задачи, провайдеры и плагины не затрагиваются.

## Публикация в npm

Тег → GitHub Actions публикует сам (Trusted Publishing, OIDC, без токенов):

```bash
git tag -a v2.2.0 -m "2.2.0" && git push origin v2.2.0
```

Workflow сам проверяет, что версия **реально появилась в реестре**, и пишет
отчёт в GitHub Release — журнал шага читает только владелец репозитория, а
релиз открыт всем.

Важно про tarball: метаданные версии видны в реестре сразу, а сам `.tgz`
отдаётся с задержкой CDN — до нескольких минут. В это окно `npm view` отвечает
успехом, а `npm install` падает с 404 на tarball. Это не сбой публикации:
подождите и повторите. Проверено на 2.2.0.

## Правила работы с файлами

**Не переписывать файлы через PowerShell.** `Set-Content`/`Out-File`/`-replace`
перекодируют файл, и русский текст превращается в мусор. Это уже дважды
ломало `lib/client.js`. Правки — только инструментом `edit`/`write`. Если нужно
проверить кодировку: `node --test test/encoding.test.mjs`.

## Что нельзя сделать в плагине

Проверено по коду DSH, не наши ограничения:

- **Перезапуск приложения.** `app.relaunch()` — только main-процесс, в preload
  его нет; пункт меню «Restart App and Host» есть только в dev-сборке.
- **Переключение чата без «принятия» сессии.** Вкладку можно создать только в
  сессии, чей store создан при показе чата. Отсюда `allowChatSwitch`.
- **Постоянный профиль Chromium.** `browser.acquire()` выдаёт
  `dsh-sidebar-browser-<uuid>` без префикса `persist:`.
- **Скачивания.** `will-download → preventDefault()`. Обходим через `fetch`.
- **Прокси и блокировка рекламы.** `setProxy` и `webRequest` — только main.
- **Скриншот фоновой вкладки.** Chromium не рисует скрытый `<webview>`.
